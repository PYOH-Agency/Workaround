# A2 — L'arrivée · Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Donner à chaque écran de quoi se présenter, faire enseigner les vides, et dire au demandeur que son espace existe.

**Architecture:** Une table de rejets adossée à `auth.users` — les deux publics en ont —, un catalogue de notices dans `domain`, une molécule qui les rend. Aucun couplage transverse : chaque page passe sa clé.

**Spec :** [A2 — L'arrivée](../specs/2026-08-10-a2-arrivee-design.md), §3 annulé (l'accueil artisan l'a livré).

### Task 1 : La table des rejets

**Files:** `src/db/schema/screen-note.ts`, `src/db/schema/index.ts`

- [ ] **Step 1 : Écrire la table**

```ts
import { pgTable, uuid, text, timestamp, primaryKey } from 'drizzle-orm/pg-core'

/**
 * Les notices qu'une personne a refermees.
 *
 * **En base, pas dans le navigateur.** L'artisan saisit au bureau et consulte
 * sur le chantier : un rejet en `localStorage` lui reservirait chaque carte sur
 * le second appareil — l'inverse exact de ce que ces cartes existent pour
 * eviter.
 *
 * `user_id` d'`auth.users`, et non `member_id` ni `requester_id` : les deux
 * publics ont des notices, et une seule table vaut mieux que deux qui font la
 * meme chose. Aucune cle etrangere, comme partout ou l'on reference
 * `auth.users` : ce schema n'est pas le notre.
 *
 * Une ligne EST le rejet. Pas de colonne « rejete » a basculer : rouvrir, c'est
 * supprimer la ligne, et l'absence se lit sans ambiguite.
 */
export const screenNoteDismissal = pgTable(
  'screen_note_dismissal',
  {
    userId: uuid('user_id').notNull(),
    /** La cle du catalogue — voir `domain/screen-notes.ts`. */
    noteKey: text('note_key').notNull(),
    dismissedAt: timestamp('dismissed_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (t) => [primaryKey({ columns: [t.userId, t.noteKey] })],
)
```

- [ ] **Step 2 :** exporter depuis `src/db/schema/index.ts`, puis `pnpm db:generate`, puis `pnpm db:reset`.

- [ ] **Step 3 : Commit** `feat: la table des notices refermees`

### Task 2 : Le catalogue des notices

**Files:** `src/domain/screen-notes.ts`, `tests/domain/screen-notes.test.ts`

Le catalogue est une donnee pure : cle, texte, et le public concerne. Il vit dans
`domain` parce que deux fonctionnalites le lisent — l'atelier et l'espace — et
que `check:feature-isolation` interdit a l'une d'importer l'autre.

Les textes sont ceux de la spec §4, mot pour mot. `/` n'a PAS de notice :
l'accueil se presente de lui-meme.

- [ ] **Step 1 : Écrire les tests** — chaque cle est unique ; chaque texte tient
  en deux phrases ; l'accueil n'a pas d'entree.
- [ ] **Step 2 :** les voir echouer.
- [ ] **Step 3 : Écrire le catalogue.** Type `ScreenNoteKey`, record `SCREEN_NOTES`.
- [ ] **Step 4 :** les voir passer.
- [ ] **Step 5 : Commit** `feat: le catalogue des notices d ecran`
