# M2 — La facture · Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permettre à une entreprise artisanale d'émettre depuis un devis signé ses factures d'acompte, ses situations de travaux, sa facture de solde et ses avoirs, avec toutes les mentions légales, et de suivre ses encaissements.

**Architecture:** Prolonge le socle de M1 sans le remettre en cause. Le devis reste le document contractuel ; la facture en découle. Deux règles distinguent radicalement la facture du devis et commandent toute la conception : **elle est immuable**, et **sa numérotation est une séquence continue sans trou**. Le modèle de données porte dès maintenant les champs exigés par la norme EN 16931, pour que le raccordement à une plateforme agréée ne demande plus qu'un adaptateur.

**Tech Stack:** Identique à M1 — Next.js 16, PostgreSQL sur Supabase, Drizzle, `@react-pdf/renderer`, Vitest, Playwright.

> **Une déviation assumée du format.** Les tâches 7 et 8 décrivent les écrans par référence à leurs équivalents de M1 (`quote-public.ts`, `quote-pdf.tsx`, `devis/page.tsx`) au lieu d'en répéter le code intégral. Ces fichiers existent, sont testés et fonctionnent ; les recopier ferait doubler ce document sans rien apprendre à personne. Le code complet est en revanche donné partout où la logique est neuve — numérotation, soldes, ventilation, encaissements —, c'est-à-dire là où se trouvent les erreurs coûteuses.

## Décisions verrouillées

**La numérotation est une séquence continue, sérialisée en base.** On ne peut ni sauter un numéro, ni en réserver un qui ne serait pas utilisé. La reprise sur collision employée pour les devis est **inacceptable ici** : un échec après attribution laisserait un trou. Le numéro s'obtient par un compteur incrémenté et lu en une seule instruction atomique (`INSERT … ON CONFLICT DO UPDATE … RETURNING`), dans la même transaction que l'insertion de la facture.

**Une facture émise ne se modifie jamais.** Pas de brouillon dans la séquence : le numéro n'est attribué qu'à l'émission. Une erreur se corrige par un **avoir**, qui est lui-même une facture et consomme un numéro.

**Le montant restant à facturer se calcule, il ne se saisit pas.** Total du devis signé, moins les factures déjà émises, plus les avoirs. Laisser l'artisan saisir un solde libre, c'est garantir des écarts avec le devis — or l'écart devis/facture est la métrique reine du passeport.

**Le suivi des encaissements n'est pas optionnel.** Les artisans sont prestataires de services : la TVA est exigible à l'encaissement, et le e-reporting des données de paiement l'exige.

// src/domain/invoice-number.ts

/**
 * Numerotation des factures.
 *
 * Contrairement au devis, la sequence doit etre **continue et sans trou** :
 * c'est une obligation comptable. Ce module ne fait que le formatage —
 * l'attribution du rang est serialisee en base (voir src/services/invoices.ts).
 */
export const INVOICE_PREFIX = 'F'

export function formatInvoiceNumber(year: number, sequence: number): string {
  if (!Number.isInteger(sequence) || sequence < 1) {
    throw new Error(`Rang de sequence invalide : ${sequence}`)
  }
  return `${INVOICE_PREFIX}${year}-${String(sequence).padStart(4, '0')}`
}
```

// src/domain/invoice-balance.ts
import type { Cents } from './money'

/**
 * Reste a facturer sur un devis signe.
 *
 * Le montant ne se saisit pas, il se calcule : total du devis, moins les
 * factures emises, plus les avoirs. Laisser l'artisan saisir un solde libre
 * garantirait des ecarts avec le devis — or l'ecart devis/facture est la
 * metrique reine du passeport.
 */
export type InvoiceType = 'deposit' | 'progress' | 'balance' | 'credit_note'

export interface IssuedInvoice {
  type: InvoiceType
  totalInclTax: Cents
}

export function remainingToInvoice(quoteTotalInclTax: Cents, issued: IssuedInvoice[]): Cents {
  const invoiced = issued.reduce(
    (sum, i) => (i.type === 'credit_note' ? sum - i.totalInclTax : sum + i.totalInclTax),
    0,
  )
  return quoteTotalInclTax - invoiced
}

export function assertInvoiceable(
  quoteTotalInclTax: Cents,
  issued: IssuedInvoice[],
  amountInclTax: Cents,
): void {
  if (amountInclTax <= 0) throw new Error('Le montant doit etre positif')

  const remaining = remainingToInvoice(quoteTotalInclTax, issued)
  if (remaining <= 0) throw new Error('Ce devis est deja integralement facture')

  if (amountInclTax > remaining) {
    throw new Error(
      'Ce montant depasse le reste a facturer. Un depassement passe par un avenant au devis.',
    )
  }
}
```

  pgTable,
  uuid,
  text,
  timestamp,
  integer,
  numeric,
  unique,
  index,

import { relations } from 'drizzle-orm'
import { company } from './company'
import { project } from './project'

/**
 * Compteur de sequence, une ligne par entreprise et par annee.
 *
 * La numerotation des factures doit etre **continue et sans trou** : le rang
 * s'obtient en verrouillant cette ligne dans la meme transaction que
 * l'insertion. La reprise sur collision employee pour les devis laisserait un
 * trou en cas d'echec, ce qui est inacceptable pour une facture.

export const invoiceCounter = pgTable(
  'invoice_counter',
  {
    companyId: uuid('company_id')
      .notNull()
      .references(() => company.id),
    year: integer('year').notNull(),
    lastSequence: integer('last_sequence').notNull().default(0),
  },
  (t) => [unique('invoice_counter_pk').on(t.companyId, t.year)],
)

export const invoice = pgTable(
  'invoice',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    companyId: uuid('company_id')
      .notNull()
      .references(() => company.id),
    projectId: uuid('project_id')
      .notNull()
      .references(() => project.id),
    // Une facture decoule toujours d'un devis signe en M2. Nullable pour
    // laisser la porte ouverte a une facture directe plus tard.
    quoteId: uuid('quote_id').references(() => quote.id),
    number: text('number').notNull(),
    type: text('type', { enum: ['deposit', 'progress', 'balance', 'credit_note'] }).notNull(),
    // Un avoir corrige une facture identifiee.
    correctsInvoiceId: uuid('corrects_invoice_id'),
    issuedAt: timestamp('issued_at', { withTimezone: true }).notNull().defaultNow(),
    dueAt: timestamp('due_at', { withTimezone: true }).notNull(),

    totalTax: integer('total_tax').notNull(),
    totalInclTax: integer('total_incl_tax').notNull(),
    // Figes a l'emission : une facture est immuable, ses mentions aussi.
    latePaymentRate: text('late_payment_rate').notNull(),
    recoveryIndemnity: integer('recovery_indemnity').notNull(),

    publicToken: text('public_token').notNull().unique(),

    index('invoice_project_idx').on(t.projectId),

```sql
-- Une facture emise ne se modifie ni ne se supprime : c'est une obligation
-- comptable. Une erreur se corrige par un avoir, qui est lui-meme une facture.
-- Comme pour le journal d'evenements, la regle est imposee par la base et non
-- par une convention de code.
--
-- Les lignes suivent le meme sort : modifier une ligne reviendrait a modifier
-- la facture.

CREATE OR REPLACE FUNCTION reject_invoice_mutation()
RETURNS TRIGGER AS $$
BEGIN
  RAISE EXCEPTION 'Une facture emise est immuable : emettez un avoir';
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER invoice_immutable
BEFORE UPDATE OR DELETE ON invoice
FOR EACH ROW EXECUTE FUNCTION reject_invoice_mutation();

CREATE TRIGGER invoice_line_immutable
BEFORE UPDATE OR DELETE ON invoice_line
FOR EACH ROW EXECUTE FUNCTION reject_invoice_mutation();
```

```typescript
// src/services/invoices.ts
import { sql } from 'drizzle-orm'
import { db } from '@/db/client'
import { formatInvoiceNumber } from '@/domain/invoice-number'

/**
 * Attribue le rang suivant de la sequence de facturation.
 *
 * `INSERT … ON CONFLICT DO UPDATE … RETURNING` incremente et lit le compteur en
 * une seule instruction atomique : deux appels concurrents ne peuvent pas
 * obtenir le meme rang, et aucun rang n'est saute.
 *
 * A appeler **dans la meme transaction que l'insertion de la facture** : un
 * rang attribue puis abandonne laisserait un trou dans la sequence, ce qui est
 * un manquement comptable.
 */
export async function allocateInvoiceNumber(companyId: string, year: number): Promise<string> {
  const [row] = await db.execute<{ last_sequence: number }>(sql`
    INSERT INTO invoice_counter (company_id, year, last_sequence)
    VALUES (${companyId}, ${year}, 1)
    ON CONFLICT (company_id, year)
    DO UPDATE SET last_sequence = invoice_counter.last_sequence + 1
    RETURNING last_sequence
  `)

  return formatInvoiceNumber(year, Number(row.last_sequence))
}

// src/services/invoices.ts (suite)
import { randomBytes } from 'node:crypto'
import { and, eq } from 'drizzle-orm'
import { invoice, invoiceLine, quote } from '@/db/schema'
import { assertInvoiceable, type InvoiceType } from '@/domain/invoice-balance'
import { computeTotals, type LineInput } from '@/domain/quote-totals'
import { missingInvoiceMentions, LEGAL_RECOVERY_INDEMNITY_CENTS } from '@/domain/legal-mentions'
import { recordEvent } from '@/services/events'

export interface IssueInvoiceInput {
  companyId: string
  quoteId: string
  type: InvoiceType
  /** Nombre de jours avant echeance, a compter de l'emission. */
  dueInDays: number
  lines: (LineInput & { label: string; unit: string })[]
  correctsInvoiceId?: string
}

export async function issueInvoice(input: IssueInvoiceInput) {
  const source = await db.query.quote.findFirst({
    where: and(eq(quote.id, input.quoteId), eq(quote.companyId, input.companyId)),
    with: { project: { with: { company: true } } },
  })

  if (!source) throw new Error('Devis introuvable')
  if (source.status !== 'signed') throw new Error('Seul un devis signe peut etre facture')

  const missing = missingInvoiceMentions(source.project.company)
  if (missing.length > 0) {
    throw new Error("Completez les mentions obligatoires avant d'emettre une facture")
  }

  const issued = await db
    .select({ type: invoice.type, totalInclTax: invoice.totalInclTax })
    .from(invoice)
    .where(eq(invoice.quoteId, input.quoteId))

  const totals = computeTotals(input.lines)
  if (input.type !== 'credit_note') {
    assertInvoiceable(source.totalInclTax, issued, totals.totalInclTax)
  }

  const now = new Date()
  const number = await allocateInvoiceNumber(input.companyId, now.getFullYear())

  const [created] = await db
    .insert(invoice)
    .values({
      companyId: input.companyId,
      projectId: source.projectId,
      quoteId: source.id,
      number,
      type: input.type,
      correctsInvoiceId: input.correctsInvoiceId ?? null,
      dueAt: new Date(now.getTime() + input.dueInDays * 86_400_000),
      totalExclTax: totals.totalExclTax,
      totalTax: totals.totalTax,
      totalInclTax: totals.totalInclTax,
      // Figes a l'emission : la facture est immuable, ses mentions aussi.
      latePaymentRate: source.project.company.latePaymentRate!,
      recoveryIndemnity: LEGAL_RECOVERY_INDEMNITY_CENTS,
      operationType: source.project.company.operationType,
      publicToken: randomBytes(24).toString('base64url'),
    })
    .returning()

  await db.insert(invoiceLine).values(
    input.lines.map((line, i) => ({
      invoiceId: created.id,
      position: i,
      label: line.label,
      unit: line.unit,
      quantity: line.quantity,
      unitPriceExclTax: line.unitPriceExclTax,
      taxRate: line.taxRate,
    })),
  )

  await recordEvent({
    type: 'invoice.issued',
    subjectType: 'invoice',
    subjectId: created.id,
    companyId: input.companyId,
    actorType: 'company',
    payload: { number, type: input.type, totalInclTax: totals.totalInclTax },
  })

  return created
}

// src/domain/payment-status.ts
import type { Cents } from './money'

/**
 * Statut de reglement d'une facture.
 *
 * Fonction pure prenant la date courante en parametre : un statut qui depend
 * de l'horloge est intestable si l'horloge est implicite.
 */
export type PaymentStatus = 'unpaid' | 'partially_paid' | 'paid' | 'overdue'

export function outstanding(totalInclTax: Cents, payments: Cents[]): Cents {
  const received = payments.reduce((sum, amount) => sum + amount, 0)
  return Math.max(0, totalInclTax - received)
}

export function paymentStatus(
  totalInclTax: Cents,
  payments: Cents[],
  dueAt: Date,
  now: Date,
): PaymentStatus {
  const remaining = outstanding(totalInclTax, payments)

  if (remaining === 0) return 'paid'
  if (now.getTime() > dueAt.getTime()) return 'overdue'
  return payments.length > 0 ? 'partially_paid' : 'unpaid'
}

    subjectId: input.invoiceId,

    actorType: 'company',
    payload: { amount, method: input.method },
  })

import { and, eq } from 'drizzle-orm'
import { db } from '@/db/client'
import { invoice, quote } from '@/db/schema'
import { computeTotals } from '@/domain/quote-totals'
import { remainingToInvoice, splitDepositByRate } from '@/domain/invoice-balance'

/** Charge le devis et ce qui reste a facturer dessus. */
async function quoteContext(companyId: string, quoteId: string) {
  const source = await db.query.quote.findFirst({
    where: and(eq(quote.id, quoteId), eq(quote.companyId, companyId)),
    with: { lines: true },
  })
  if (!source) throw new Error('Devis introuvable')

  const issued = await db
    .select({ type: invoice.type, totalInclTax: invoice.totalInclTax })
    .from(invoice)
    .where(eq(invoice.quoteId, quoteId))

  return { source, issued, totals: computeTotals(source.lines) }
}

/** Situation de travaux : un pourcentage d'avancement, ventile par taux. */
export async function issueProgress(
  quoteId: string,
  percent: number,
  _state: InvoiceFormState,
): Promise<InvoiceFormState> {
  const { companyId } = await currentCompany()

  try {
    const { totals } = await quoteContext(companyId, quoteId)
    const created = await issueInvoice({
      companyId,
      quoteId,
      type: 'progress',
      dueInDays: 30,
      lines: splitDepositByRate(totals.byRate, percent).map((l) => ({
        label: `Situation de travaux — ${percent} % d’avancement`,
        unit: 'u',
        quantity: '1',
        unitPriceExclTax: l.unitPriceExclTax,
        taxRate: l.rate,
      })),
    })
    redirect(`/factures/${created.id}`)
  } catch (e) {
    return { error: (e as Error).message }
  }
}

/**
 * Facture de solde : exactement ce qui reste, jamais une saisie libre.
 *
 * Le montant se deduit du devis et des factures deja emises. C'est ce qui
 * garantit que la somme des factures egale le devis — donc que la metrique
 * « ecart devis vers facture » du passeport a un sens.
 */
export async function issueBalance(
  quoteId: string,
  _state: InvoiceFormState,
): Promise<InvoiceFormState> {
  const { companyId } = await currentCompany()

  try {
    const { source, issued, totals } = await quoteContext(companyId, quoteId)

    const remaining = remainingToInvoice(source.totalInclTax, issued)
    if (remaining <= 0) return { error: 'Ce devis est déjà intégralement facturé.' }

    // Le reste est exprime TTC : on le ramene en pourcentage du devis pour le
    // ventiler sur les memes taux, plutot que de recalculer une base.
    const percent = (remaining / source.totalInclTax) * 100

    const created = await issueInvoice({
      companyId,
      quoteId,
      type: 'balance',
      dueInDays: 30,
      lines: splitDepositByRate(totals.byRate, percent).map((l) => ({
        label: 'Solde du devis',
        unit: 'u',
        quantity: '1',
        unitPriceExclTax: l.unitPriceExclTax,
        taxRate: l.rate,
      })),
    })
    redirect(`/factures/${created.id}`)
  } catch (e) {
    return { error: (e as Error).message }
  }
}

/** Avoir : corrige une facture identifiee, sans plafond de depassement. */
export async function issueCreditNote(
  invoiceId: string,
  _state: InvoiceFormState,
): Promise<InvoiceFormState> {
  const { companyId } = await currentCompany()

  try {
    const target = await db.query.invoice.findFirst({
      where: and(eq(invoice.id, invoiceId), eq(invoice.companyId, companyId)),
      with: { lines: true },
    })
    if (!target || !target.quoteId) return { error: 'Facture introuvable.' }

    const created = await issueInvoice({
      companyId,
      quoteId: target.quoteId,
      type: 'credit_note',
      dueInDays: 0,
      correctsInvoiceId: target.id,
      lines: target.lines.map((l) => ({
        label: `Avoir sur ${target.number} — ${l.label}`,
        unit: l.unit,
        quantity: l.quantity,
        unitPriceExclTax: l.unitPriceExclTax,
        taxRate: l.taxRate,
      })),
    })
    redirect(`/factures/${created.id}`)
  } catch (e) {
    return { error: (e as Error).message }
  }
}

// src/domain/invoice-balance.ts (suite)
import type { TaxBreakdown } from './quote-totals'

/**
 * Ventile un acompte sur les taux de TVA du devis qu'il finance.
 *
 * Un acompte porte la TVA du devis : appliquer un taux unique a un devis
 * multi-taux produit une declaration de TVA fausse. Le dernier centime est
 * affecte a la derniere ligne pour que la somme tombe juste.
 */
export function splitDepositByRate(
  byRate: TaxBreakdown[],
  percent: number,
): { rate: number; unitPriceExclTax: Cents }[] {
  if (percent <= 0 || percent > 100) {
    throw new Error(`Le pourcentage doit etre compris entre 1 et 100 : ${percent}`)
  }

  const totalBase = byRate.reduce((sum, b) => sum + b.baseExclTax, 0)
  const target = Math.round((totalBase * percent) / 100)

  const lines = byRate.map((b) => ({
    rate: b.rate,
    unitPriceExclTax: Math.round((b.baseExclTax * percent) / 100),
  }))

  // Rattrapage de l'ecart d'arrondi sur la derniere ligne.
  const drift = target - lines.reduce((sum, l) => sum + l.unitPriceExclTax, 0)
  if (drift !== 0 && lines.length > 0) lines[lines.length - 1].unitPriceExclTax += drift

  return lines
}
```

## Ce que l'exécution a corrigé dans ce plan

Consigné après coup, comme pour M1 : ce sont les défauts que seule l'écriture du code a révélés.

**Le rang était attribué hors transaction.** Le plan appelait `allocateInvoiceNumber` puis insérait la facture séparément — alors que son propre commentaire exigeait le contraire. Un échec entre les deux laissait le compteur incrémenté, donc **un trou dans la séquence** : exactement le manquement comptable que toute cette conception existe pour empêcher. `issueInvoice` ouvre désormais une transaction et lui passe l'exécuteur. Le test *« rend le rang si la transaction échoue »* verrouille la propriété.

**`redirect()` était appelé dans le `try`.** Next signale la navigation en levant une exception : le `catch` l'aurait interceptée et affiché « NEXT_REDIRECT » comme message d'erreur au lieu de naviguer. Toutes les actions d'émission appellent `redirect` après le bloc.

**Le solde était calculé en pourcentage du reste TTC.** Convertir un reste en pourcentage puis le re-ventiler ajoute un arrondi de plus. Trois situations successives suffisaient à laisser un résidu de quelques centimes qu'aucune facture ne pouvait solder — le devis restait indéfiniment ouvert. `remainingByRate` soustrait directement, base par base. Le test *« solde un devis au centime près après trois situations arrondies »* le démontre.

**Le premier test de la Task 9 se contredisait.** Il vérifiait le refus de facturer un devis non signé, sur le devis que l'étape suivante basculait en signé. Chaque test fabrique désormais son propre devis : la facture étant immuable, rien ne se nettoie entre deux tests, et partager un devis les rendrait dépendants de leur ordre.

**La vérification d'immuabilité ne vérifiait rien.** `UPDATE invoice SET number='X'` sur une table vide n'affecte aucune ligne, ne déclenche rien, et rapporte un succès. Les quatre mutations — `UPDATE` et `DELETE`, sur la facture et sur ses lignes — ont été vérifiées sur des lignes réelles.

**Les tests de service n'étaient pas rejouables.** Ils s'appuyaient sur l'entreprise du jeu de données ; le compteur de séquence survivant à la suite, le deuxième `pnpm vitest run` échouait sur un compteur déjà consommé. Ils s'isolent maintenant par entreprise générée, comme le fait déjà `events.test.ts`.

Deux ajustements mineurs de même nature : `missingInvoiceMentions` n'exige plus la durée de validité, qui n'a de sens que sur un devis ; et le formulaire d'encaissement se vide par remontage plutôt que par un effet appelant `setState` en cascade — le linter l'a refusé, à raison.

**La Task 10 a été remontée avant la Task 8.** Écrire sciemment un taux de TVA faux pour le corriger deux tâches plus loin n'avait pas de sens.
